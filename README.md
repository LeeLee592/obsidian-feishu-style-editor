# Feishu Style Editor

为 Obsidian 增加飞书风格的文档编辑能力，同时保留完整的 Obsidian Markdown 语法。

## 功能

### 两个不同的块菜单

飞书里行前的 `+` 与行首的 `/` 打开的是**两个不同的面板**，插件照此实现。

**`/` 斜杠菜单** —— 可搜索的块列表：

- 顶部关键字栏直接显示已输入的 `/` 加过滤词（`/标题`），提示文字为 `输入关键词`；
- 分组标题（`基础` / `常用`）同飞书，每组是一条条「图标 + 名称」的行，右侧标注 `#` `##` 等快捷标记；
- 输入关键字即时过滤，此时合并为一条扁平结果列表；`↑` `↓` 移动，`Enter` 确认，`Esc` 关闭并撤销已输入的 `/`；
- 行中间（URL、`and/or`）的 `/` 不会被拦截，仍是普通字符。

**`+` 插入面板** —— 没有关键字栏，改为飞书那样的图标宫格：

- `基础` 是六列纯图标宫格（Text、Heading 1–3、有序/无序/任务列表、代码块、引用、分隔线、链接、折叠列表），名称放在悬停提示与无障碍标签里；
- `常用` 是带名称的列表（Callout、Table、Image、Video or file、Formula…），可展开二级菜单的条目（如 Callout）右侧带 `›`，二级菜单里可选 note / tip / info / success / question / warning / danger / example。

两个面板的分组之间都以飞书那样的细分割线隔开；光标所在的块（`# 标题`、`- 列表`…）在面板里带蓝色图标底色，一眼能看出当前是什么块。悬浮工具栏左段的 `转换为` 打开的是同一份块列表（等同斜杠菜单去掉关键字栏）。

### 悬浮工具栏

选中文本后弹出分段式工具栏，形如飞书的浮动条：

`转为 ▾` │ `B` `I` `S` `U` │ `` ` `` `==` 🔗

- 左段是块类型转换入口（`Turn into`），展开完整块面板。
- 中段是行内字形：加粗、斜体、删除线、下划线（`<u>…</u>`）。
- 右段是代码、高亮、链接；高亮按钮下方带一条黄色标记，对应飞书工具栏上的颜色示意。

点击任一段的按钮只改 Markdown 源码，工具栏在应用块命令后会自动收起，避免遮住刚生成的内容。

### 行前 `+` 手柄

光标所在行左侧显示 `+`，点击打开上面的 `+` 插入面板（宫格那一个，不是斜杠菜单）：

- 空行直接写入块标记；
- 有内容的行**就地转换**（`正文` → `# 正文`）；
- 行内选中文本会随块一起移动。

上述功能均可在插件设置中分别开关（开关会持久化）。

### 配色

整套 UI 取飞书的配色：白底 `#fff`、正文 `#1f2329`、分隔线与描边 `#dee0e3`、悬停 `#f2f3f5`，光标所在块用飞书蓝 `#3370ff` 配 `#e1eaff` 底色。深色主题下换成对应的一组颜色。所有颜色都是 `--fse-*` 变量，可以用 CSS 片段整体改色，例如：

```css
body {
	--fse-accent: #ff8800;
	--fse-selected: #ffefdf;
}
```

图标配色照飞书来：列表行的图标默认是彩色的——标题、列表、引用与链接用飞书蓝 `#3370ff`，代码块与表格用绿色，分隔线与高亮块用橙色，图片用黄色，公式用紫色；`+` 面板顶部的图标宫格则同飞书一样保持黑色单色。设置里关掉 **Colored block icons** 会让列表行也退回单色。

## 开发

```bash
pnpm install
pnpm run dev         # 开发模式（监听）
pnpm run build       # 构建 production
pnpm run lint        # ESLint
pnpm run deploy:test # 部署到 Test/ vault
pnpm run verify:live # 对运行中的 Obsidian 做端到端验证
```

### 真机验证

`verify-live.sh` 通过 Obsidian CLI 与 Chrome DevTools Protocol 驱动真实运行的应用，共 53 项检查：斜杠菜单的开合、关键字栏（`/` 加过滤词）、过滤与执行、转义撤销、方向键选择；`+` 面板的两段结构——图标宫格 + 常用列表、无关键字栏、二级菜单箭头；两套菜单的结构差异；悬浮工具栏；`+` 手柄；飞书配色（读取运行中的计算样式：底白、发丝线、蓝底当前块、宫格单色、列表行彩色）；设置持久化与彩色开关；控制台无插件报错。

脚本遵循「不抢窗口」原则：CodeMirror 的输入管线只接受可信事件，因此需要真实按键的检查集中在约 10 秒的前台阶段——脚本先记录当前前台应用并明确提示，结束后再切回去；其余检查全部在后台完成。

```bash
pnpm run build && pnpm run deploy:test
# 让 Test vault 处于前台后
pnpm run verify:live
```

脚本会把按键事件派发到目标编辑器自身的 DOM，而不是走操作系统键盘队列，避免与正在使用该窗口的人抢占输入。
